# PonStamp の設計（作る人向け）

使う人・配る人向けの説明は [README.md](../README.md)、作業の決まりは [CLAUDE.md](../CLAUDE.md)。

## 1. 役割の分け方（HTML＋Rust）

| 層 | 場所 | 受け持つこと |
|---|---|---|
| 画面 | `app/`（HTML・CSS・JS。ES モジュール。exe に埋め込む） | 印を描く（`stamp.js`）・入力と設定の画面（`app.js`・`settings.js`）・外との窓口（`backend.js`）・登録した印の並びを直す関数（`presets.js`）・ものさし（`ruler.js`）・画面の文字の大きさ（`zoom.js`） |
| 部品 | `core/`（Rust・`ps_core`） | 窓に依らない処理（名前と版・保存・PNG の解像度・release.json と名乗りの形・配る ZIP・置き場を探す・取り込む・配る・ショートカットの決まり）。窓と道具が使う |
| 窓 | `desktop/`（Rust・Tauri 2） | 窓・通知領域の常駐・1 つだけ起動・保存（解像度つき PNG）・クリップボード・Windows 起動時の常駐・ショートカット・配布と更新 |
| 道具 | `tools/`（Rust の `ps-tools`・Node） | `cargo tools <命令>`: 配る ZIP（`build`・`notes`）・版の記録（`release`）・更新の通し（`verify`）・採点（`score`）・Windows 向けの確かめ（`wincheck`）・自己診断の結果（`selftest`）。Node: 撮影（`ui-*.mjs`）・画面と印影の評価関数（`*-eval.mjs`） |

- 前の形（Flask の `app.py` がポート 8765 で画面を出し、Edge のアプリの窓で開く）をやめた。ポートを開かないので、プロキシ・ポートの取り合い・古いサーバーの残りが無い
- Python は使わない（動くのにも、作る・確かめるのにも）。配る物は exe 1 つ。道具は Rust（窓と同じ部品 `ps_core` を使うので、
  release.json・名乗りの形・名前の決まり・ZIP の作り方が窓の取り込みと食い違わない）。ブラウザを動かす撮影と画面の評価関数だけ Node
- 画面は `backend.js` だけを通して外と話す。窓の中は Rust の命令（`invoke`）、ふつうのブラウザ（撮影・試し）では localStorage とダウンロードで代わりをする。
  撮影では覚えの `demo` に窓の答え（版・常駐・更新・配布）を入れ、その状態の画面を見せる

### Rust の中の分け方

- Rust はワークスペース（最上位の `Cargo.toml`・`Cargo.lock`・`target/`。`core`・`desktop`・`tools`）。道具は窓（Tauri・WebKitGTK）を組まずに作れる
- `ps_core`（`core/src/lib.rs`。窓に依らない・試験から直に呼ぶ）: `pack`（配る ZIP を作る）・ `brand`（名前と版）・`paths`（作業場所）・`store`（`state.json`）・`files`（保存）・
  `pngx`（pHYs・DIBV5）・`release`（置き場を探す）・`update`（写す・取り込む・入れ替える・戻す）・`distribute`（配る）・`install`（ショートカットの決まり）
- exe（`desktop/src/main.rs` ほか）: `commands`（画面の命令）・`tray`（通知領域）・`shellmenu`（エクスプローラーの右クリック）・`updater`（裏の確かめ）・
  `lnk`（.lnk）・`clip`（クリップボード）・`autostart`（HKCU の Run）・`proc`（PID を待つ・名前で探す・終わらせる）・`locate`（場所と記録）
- Windows の部品を直に呼ぶ所は `#[cfg(windows)] mod imp` に分け、ほかの OS では同じ決まりを小さなファイルで真似る（Linux の本物の窓で通しの確かめができる）

## 2. 名前と版（1 か所の定義）

- `app/brand.json`: 名前（`name`・`subtitle`・`exe`）・目印 `app_id`（変えない）・作業場所の名前・前の形の置き場・更新の置き場の既定。
  Rust（`brand.rs` が取り込む）・道具・画面が同じファイルを読む。`tauri.conf.json`・`Cargo.toml` との食い違いは `brand.rs` の試験が止める
- `app/version.json`: 版・更新履歴・配った版の中身の要約（`release`）。配る物（`app/`・`core/`・`desktop/`・ワークスペースの `Cargo.toml`・`Cargo.lock`）を変えて
  版を上げ忘れると `tools/src/release.rs` の試験が止める（`cargo tools release --release` で要約を書き、`desktop/Cargo.toml`・`tauri.conf.json`・
  `Cargo.lock` の窓の版もそろえる）。道具の部品を変えて `Cargo.lock` が変わったときも、配る物の作り方が変わりうるので版を上げる

## 3. 起動の流れ

LotScope と同じ形（入口 → 版ごとの写し）。

```
共有・BOX の exe ─(この PC へ写す: localize)→ app\PonStamp.exe（入口）─(版ごとの写し: handoff)→ desktop\<版-大きさ-時刻>\PonStamp.exe（窓）
配る入口（置き場の exe）─(配る版を取り込んで据える: install_from_entry)→ app\ ……
```

1. `hand_off`（窓を作る前）: 配る入口なら配る版を取り込んで `app\` に据え、共有の配る形なら（新しければ）`app\` へ写し、入口を開いて終わる。
   入口は版ごとの写しを開いて終わる。写す仕事は `update\install.lock` で 1 台 1 つ（ダブルクリックの 2 回押しでぶつからない）
2. 窓（写し）: 前の版の窓に代わる（`supersede`）→ 1 つだけ起動（2 つめは前の窓を出すだけ）・通知領域のアイコン・閉じると隠す。
   **前の版の窓に代わる**: 写しは `app\` の exe から作るので、ほかの写し（`desktop\` の別のフォルダ）から動いている窓は `app\` が入れ替わる前の版。
   それを終わらせてから 1 つだけ起動の受け口を作る（`update::stale_windows` が選び、`proc` が終わらせる）。同じ写しの窓（同じ版）はいつもどおり前に出す。
   これが無いと、古い版が常駐している間に新しい版の exe を開いても古い窓が前に出るだけで、新しい版に移れない
   （1.0・1.1 は窓口が解像度を捨ててコピー・保存・版を置くが止まり、1.2 の exe を開いても常駐している 1.1 のままだった）
3. `start`（裏の糸）: 入れ替えた直後の版の見張り（`guard_applied`）→ 控えた置き場を確かめる（5 秒まで待つ。`launch_check`）→
   取り込み済みの版へ入れ替え（`apply_staged`）。入れ替えたら入口で開き直す → 片付け（ショートカットを直す・古い写しを消す・前の形の常駐を移す）→ 窓を出す
   （`--tray` なら隠したまま）→ 更新の係を走らせる
4. 画面が出たら `page_ready`: 入れ替えた直後の印（`update\applied.json`）を消す。**印が残ったまま次の起動になったら、画面が出なかったとして控えの前の版へ戻す**

開発（作業ツリーの `target` の下・`--here`・`PONSTAMP_NO_HANDOFF`）はこの PC へ写さずそのまま動く。

## 4. 配布と更新

置き場の形と使う人・配る人の手順は README。仕組み:

- 目印: 版のフォルダの `release.json`（`schema`・`app_id`・`version`・`zip`・`sha256`・`exe`）、配る版の `distribute.json`、配る形の名乗り `app.json`
- 置き場の形: `<置き場>\<アプリのフォルダ>\{distribute.json・配る入口・<版を置くフォルダ>\<版>\{release.json・ZIP}}`。
  フォルダの名前は設定（`releaseFolder`・`versionsFolder`。空なら既定のアプリの名前・`versions`）で、`distribute::Layout` が持つ。
  アプリのフォルダは、置き場そのものがアプリのフォルダ（配る版の覚えがある・名前が同じ）ならそこ、名前を決めていればその名前、
  決めていなければ今あるフォルダ（配る版の覚え → いちばん新しい版のアプリのフォルダ）を使い続ける
- 置き場の下を 4 段まで・600 フォルダまでたどり、目印の `app_id` が合う物だけを使う（名前でなく目印で見つけるので、名前を変えても・1.1 までの直下に置いた版も読める）。
  「.」で始まるフォルダ（置いている途中・消している途中）は見ない
- 取り込み: 手元へ写す → 指紋（SHA-256）を照らす → 展開（危ない名前・1 GB 超・名乗りを超える中身は断る）→ 名乗りの目印と版を確かめる → `update\stage\`
- 配る版が決まっていればその版（前の版へ戻すときも）、無ければいちばん新しい版。起動できなかった版（`update\FAILED.json`）は選ばない
- 置く: `.<版>.placing-<pid>` に写して指紋を確かめ直し、`release.json` を書いてから名前を変える。消す: 先に `.<版>.removing-<pid>` へ名前を変えてから消す
- 写した exe からは「インターネットから来た」印（`Zone.Identifier`）を外す（開くたびの警告を出さない）
- 更新の置き場の候補: 設定の値（無ければ `brand.json` の既定）＋ 配る入口から入れた PC が控えた入口の置き場

### 右クリックからコピー（通知領域・エクスプローラー）

- 通知領域: メニューの「登録した印」を押すと、Rust が画面へ `ps:copy`（番号 | last）を送り、隠れた画面が描いて `copy_png` を呼ぶ
- エクスプローラー（`shellmenu.rs`）: 常駐している間だけ、HKCU の `Directory\Background\shell\<名前>` に段（`SubCommands`）と登録した印の行を置く。
  行は `"<入口の exe>" --copy <番号 | last>`。入口 → 版ごとの写しへ引数を渡し、1 つだけ起動の仕組みで動いている窓へ届く（`ps:copy`）。
  動いていなければ窓を出さずに起き、画面ができたら（`page_ready`）コピーする。起動したとき・登録した印を変えたときに書き直し、終了（`RunEvent::Exit`）で外す

### 登録した印（並び・上書き・名前・削除）

- 並び `[{name, s}]` を直すのは `presets.js` の純粋な関数（上書き・名前・前へ/後ろへ・削除・足す・変えたか・Ctrl+番号）。どれも新しい並びを返し、
  同じ名前を断る（同じ名前があると、どれを呼ぶか分からない。上書きは「いまの印」の行の「上書き」で明示する）
- 「変えたか」は、呼び出した直後の印（書体の置き換えなどを済ませた形）を控えに取り、いまの印と比べる（地・解像度は数えない）。
  控えを保存した値にしないのは、呼び出した時点で値が整えられ、何もしなくても「変更あり」になるため
- 並べた順は Rust にそのまま渡り、通知領域・右クリックのメニューの順と Ctrl+番号になる。削除は即座に消し、知らせの「元に戻す」で並びと呼び出しを戻す

## 5. 保存とクリップボード（解像度）

画面の canvas が作る PNG には解像度が無く、Word などは 96 dpi と見なす（600 dpi・10.5mm の 248px が 65.6mm になる）。そこで:

- 保存: Rust が PNG の `IHDR` の直後に `pHYs`（1 m あたりの点）を書く（前の `pHYs` は外す）。自己診断が書いた PNG を読み戻して確かめる
- コピー（Windows）: 登録した形「PNG」（透明・`pHYs` つき）と `CF_DIBV5`（BGRA・下から上・`XPelsPerMeter` つき。まったく透明な画素は白）を置く。
  WebView の `navigator.clipboard` は画像を作り直して解像度を落とすので使わない（ほかの OS は使う）
- 各 Office アプリが貼り付けのとき、どちらの形のどの解像度を読むかは確かめていない（README に書いた）。利用者が確かめられるよう、
  幅 50mm のものさし（`ruler.js`。1mm ごとの目盛り・白地）を印と同じ道でコピー・保存できる。`tools/ruler-eval.mjs` が、解像度ごとの画素の数と
  目盛りの位置（どの線も半画素以内）を確かめる

## 6. 印影の精度

`tools/stamp-eval.mjs`（評価関数）が見本 16 種（1〜15 字・平たい字・込み入った字・長い上段・英字）を本物の描き方で描き、枠と字を描き分けて測る:

| 物差し | 基準 | 根拠 |
|---|---|---|
| ゆがみ（字の縦横の伸び縮みの比） | ≤ 1.4 | 和文の組版で長体・平体を 70% までに留める慣習（1/0.7 ≈ 1.43） |
| 字と枠・線の隙間 | ≥ 2.5%（一辺に対して） | 印影を縮めて貼っても、字と枠がくっついて見えない |
| 列の高さのそろい | ≥ 0.97 | 短い列が上に寄って下が空く（空きのます）のを捉える |
| ますの片寄り・字の左右のずれ（1 列・1 行のとき） | ≤ 1.0% | 中心に置く |

直す前は 6/16、直した後は 16/16（IPAex 明朝・ゴシックの 2 通り）。直したこと: ゆがみの上限を 1 か所の定数に統一・1 行の字の高さを基準字「国」で決める
（「一」が棒にならない。横には伸ばさず、長い行は 70% まで詰め、それでも入らなければ小さくする）・短い列も列の高さいっぱいに割り付ける・
角印の列数を、ゆがみの上限の中で字が最も大きく描ける並べ方で選ぶ。

測る途中で物差しの誤りも直した: 字のインクの重心（画数の多い字で動き、並べ方でなく字の性質を測ってしまう）・ますの面積の埋まり（ますの内側の余白まで空きと数える）を
やめ、2 列以上では字の左右のずれを見ない（字の幅の違いで動く）。

### 字の大きさ・日付・かすれ

- 字の大きさ（`textSize`・%）: 小さくするときは並べ方が決めた字の箱をその場で縮め、大きくするときは字の並び全体を印の中心から広げる
  （箱の位置も同じ倍率で外へ。字どうしの間も同じ割合で広がるので、字が重ならない）。100% は字と枠の隙間を保つ大きさ。
  上限は「少しはみ出る程度まで」（利用者が決めた。2026-11-04）: 字は枠の線に重なってよく、印の外形の外へは枠の太さの半分まで（既定の枠 4% → 2%）しか出ず、
  画像の端で切れず、字の箱どうしが重ならない、いちばん大きい所。`tools/textsize-eval.mjs` が見本ごとに 100〜200% を 5 刻みで測って出し、`TEXT_SIZE.max` と食い違えば止める
  （認印 125%・日付印 125%・角印 115%。前は隙間の基準の中で 110%・110%・100%。
  初めは箱をその場で広げて測り 135%・135%・130% としたが、2 字以上で隣の字に食い込んでいた〈作った後の見本で見つけた〉ので、並び全体を広げる形に直し、字の重なりも測るようにした）
- 日付（`dateTpl`）: Excel の表示形式と同じ記号で書く書式（yyyy・yy・e・ee・g・gg・ggg・m・mm・d・dd・aaa・aaaa。"…" の中はそのまま）。
  決まった書式（`DATE_PRESETS`）14 通り（西暦・スラッシュ・和暦・漢字）から選ぶか、自分で書く。元号は始まる日で決める（令和・平成・昭和）。
  1.4 までの形（`dateFmt` × `dateSep` × `pad`）は `merge` が書式に直して引き継ぐ（登録した印も）
- かすれ（利用者が決めた: 字が読めなくならないよう、枠の縁が欠ける形にする。2026-11-04）: 枠と字を分けて描き、それぞれのインクの縁からの近さ
  （ならしたインクの薄さ）と模様（大・中・細かい 3 つの粗さ）を足して境を越えた所を欠く。欠けは縁から内へ塊で食い込み、強さに沿って深く・多くなる。
  字には枠の 0.4 倍だけ効かせる（縁が少し荒れるだけ）。`tools/kasure-eval.mjs` が 3 種類の印 × 模様 4 通りで、枠と字の欠けと、欠けが縁からか（地とつながるか）を測る

| 物差し | 基準 | 直す前（1.4） | 直した後 |
|---|---|---|---|
| 既定（10）の枠の欠け | 0.3〜4% | 0% | 3.5% |
| 既定（10）の字の欠け | ≤ 0.3% | 0% | 0.3% |
| いちばん強い（100）の枠の欠け | 12〜40% | 3.2% | 30.7% |
| いちばん強い（100）の字の欠け | ≤ 3%（字が読める） | 8.5% | 1.1% |
| 枠の欠けの増え方 | 単調・R² ≥ 0.95・10 刻みのむら ≤ 2.5 | R² 0.51・むら 5.1 | R² 1.00・むら 1.1 |
| 欠けは縁から（50・100） | ≥ 85% | 100% | 99% |

  前（1.4）は印全体に同じ模様で穴を開け、薄れさせていた。強くすると字から先に欠け（字は線が細いので）、枠はほとんど欠けなかった

## 7. 確かめ方

- `push 前の確かめ`（CLAUDE.md）: 構文・lint・試験（Rust: 部品・窓・道具 70 件ほど。道具の試験は版の上げ忘れ・配る ZIP の形・採点の決め方も確かめる）
- 自己診断（`PONSTAMP_SELFTEST=<結果>`）: 本物の窓で、描く・mm と dpi どおりの画素の数・解像度つきの保存（Rust が読み戻す）・クリップボード（印・ものさし）・登録した印・画面のエラー
- 画面の評価関数（Node）: `presets-eval.mjs`（並びを直す関数）・`ruler-eval.mjs`（ものさしの精度）・`presets-flow-eval.mjs`（本物の Chromium で押す:
  1 手でコピー・Ctrl+番号・変更あり・上書き・名前・並べ替え・削除と元に戻す・ものさし。21 項目）
- 更新の通し（`cargo tools verify`）: 共有から写る → 裏で取り込む → 開き直すと入れ替わる（控えが残る・共有を指すショートカットが直る）→ 閉じている間に置いた版が 1 回で入る →
  起動できない版は次に開くと戻り印が付く → 配る版を戻す → 新しい PC が配る入口から入る → 古い版が常駐している間に新しい版の exe を開くと新しい版に代わる →
  共有は 1 ファイルも変わらない・窓が残らない（20 項目）
- CI: `ci.yml`（Linux・WebKitGTK）と `desktop.yml`（Windows・WebView2。本番の exe・自己診断・更新の通し・配る ZIP・main では Releases へ）
- Windows だけのコード: `cargo tools wincheck`（Linux から Windows 向けに clippy）
